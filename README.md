# ПУЛЬС

Платформа учета личного состава
Военно-космической академии имени А.Ф. Можайского.

## Если вам прислали эту папку

В комплекте уже лежит `puls-images.tar`: образы программы, Postgres и nginx. Качать их из интернета не нужно. Установщик Docker в папку не входит — его ставят на сервер отдельно, пока сеть ещё есть. Дальше сервер может работать без интернета.

1. Docker должен быть установлен и запущен. Скопируйте настройки:

```bash
cp .env.example .env
```

2. Откройте `.env`. Замените `SECRET_KEY` на длинную случайную строку. В `CORS_ORIGINS` укажите адрес, по которому сотрудники откроют сайт, например `http://10.0.0.5:5173`.

3. Загрузите образы и запустите программу. На Windows скрипт запускают в Git Bash, не в PowerShell:

```bash
./scripts/load_offline.sh puls-images.tar
```

Успех — строка `Health OK`. Сайт: `http://<IP-сервера>:5173`.

## Стек

- **Backend:** FastAPI, PostgreSQL, SQLAlchemy 2.0, WebSockets
- **Frontend:** Vite, React, TypeScript, Tailwind CSS
- **Deploy:** Docker Compose

## Какой запуск вам нужен

Это две разные задачи. Команда для одной не открывает программу в другой.

**Открыть программу у себя**, на компьютере с интернетом. Нужен раздел «Запуск у себя». Сайт будет на `http://localhost:5173`.

**Поставить программу на сервер академии**, у которого нет интернета. Сначала на компьютере с интернетом собирают файл `puls-images.tar`. Потом этот файл и папку проекта везут на сервер и там запускают. Архив сам сайт не открывает: ни у вас на компьютере, ни в браузере. Нужен раздел «Сервер без интернета».

## Запуск у себя

Docker Desktop должен быть запущен. В папке проекта:

```bash
cp .env.example .env
docker compose up --build
```

Первая сборка скачивает образы из интернета и может занять несколько минут. Когда в терминале появятся строки `Application startup complete` и `VITE ... ready`, откройте `http://localhost:5173`.

- Сайт: http://localhost:5173
- Проверка API: http://localhost:8000/api/health
- Описание API: http://localhost:8000/docs

Остановить программу: в том же терминале `Ctrl+C`. Контейнеры останутся, база не сотрётся. Снова запустить без пересборки: `docker compose up`.

`docker compose down -v` останавливает контейнеры и **удаляет базу**. Флаг `-v` стирает всех людей, расход и регистрации дежурных. Для обычной остановки его не используйте.

pgAdmin по желанию: `./scripts/pull-pgadmin.sh`, затем `docker compose --profile tools up -d pgadmin`. Адрес http://localhost:5050. Схема базы: ПКМ по БД `asmrlsp` → **Generate ERD**. Если загрузка образа падает с `EOF`, см. [docker/pgadmin/README.md](docker/pgadmin/README.md).

### Без Docker

Так запускают только для разработки, когда Postgres уже доступен по `DATABASE_URL`.

```bash
cd backend && pip install . && uvicorn app.main:app --reload
cd frontend && npm install && npm run dev
```

## Схема ID

| Тип | Правило | Пример |
|-----|---------|--------|
| Расположение | 1001 Академия, 1002 ВГ №6 (Пушкин), 1003 ВГ №61 (Лехтуси) | 1003 — ВГ №61 |
| Факультет | id = номер, **без расположения** | 6 — 6-й факультет |
| Курс | id = факультет×10 + год (1–5); parent = расположение | 1 фак 4 курс → **14** |

Каждый пост наряда входит по **логину и паролю** (статичные, без ежедневной смены):

| Роль | Логин | Пароль по умолчанию |
|------|-------|---------------------|
| ДПА | `dpa` | `dpa-naryad` |
| ДПФ 1 факультет | `dpf-1` | `dpf-1` |
| ДПК 1 фак 1 курс | `dpk-11` | `dpk-11` |
| ДПФ именованного подразделения | `dpf-2001` | `dpf-2001` |
| ДПК группы офицеров | `dpk-20011` | `dpk-20011` |

Именованные подразделения **постоянного состава** (id 2001+) создаются в админке с произвольным названием; внутри добавляются **группы офицеров** с отдельными ДПК. Переменный состав — только через номерные факультеты и курсы.

## Демо-учётки

| Роль | Вход |
|------|------|
| Администратор | `admin` / `admin123` |
| Начальник | `nachalnik` / `nachalnik123` |
| ДПА (наряд) | `dpa` / `dpa-naryad` |
| ДПК 1 фак 1 курс | `dpk-11` / `dpk-11` |
| ДПФ 1 факультет | `dpf-1` / `dpf-1` |

### Расход

- **Расположение** — сумма курсов в нём (без офицеров факультетов)
- **Факультет** — все курсы факта (любые расположения) + постоянный состав
- **Вся академия** — все курсы + офицеры всех факультетов

Админ в **ОШС**: два дерева (расположения / факультеты), добавление курса в расположение, перенос курса.

## Сервер без интернета

Сервер академии в интернет не выходит. Команда `docker compose up --build` там не сработает: Docker пойдёт скачивать образы `python`, `node`, `postgres` и `nginx`, а сборка ещё потянет пакеты Python и npm. В терминале будет `lookup registry-1.docker.io: no such host`.

Docker на сервере ставят заранее, пока сеть ещё есть, или с офлайн-установщика. После отключения интернета поставить его с этого сервера нельзя.

Перенос состоит из двух мест.

1. Компьютер с интернетом собирает файл `puls-images.tar`. Сайт при этом не запускается.
2. Сервер загружает этот файл и только тогда поднимает программу.

### 1. Собрать архив на компьютере с интернетом

Откройте папку проекта. Файл `.env` нужен скрипту, даже если значения в нём пока учебные:

```bash
cp .env.example .env
```

Скрипт написан для bash. В обычном PowerShell команда `./scripts/pack_offline.sh` ничего полезного не сделает. На Windows запустите её через Git Bash из папки проекта:

```powershell
& "C:\Program Files\Git\bin\bash.exe" ./scripts/pack_offline.sh
```

На Linux из папки проекта:

```bash
./scripts/pack_offline.sh
```

Скрипт собирает образы программы, скачивает Postgres и nginx и складывает их в один файл. Это долго и требует интернет. В конце терминал пишет:

```text
Готово: /путь/к/проекту/puls-images.tar
На флешку вместе с tar положите каталог проекта без node_modules, .git и .env.
Файл .env подготовьте отдельно: SECRET_KEY, CORS_ORIGINS и SEED_DEMO_DATA=false.
На сервере: ./scripts/load_offline.sh puls-images.tar
```

Строка `Готово` значит только одно: файл `puls-images.tar` создан в папке проекта. Контейнеры не запущены. Браузер открывать не нужно. Команду `load_offline.sh` на этом компьютере тоже не запускают: она для сервера.

Этого файла нет в git. Он записан в `.gitignore`, поэтому `git clone` и `git pull` его не привезут. Образы появляются только после `pack_offline.sh` на компьютере с интернетом. На флешку или по локальной сети копируйте папку целиком уже после этой команды, вместе с `puls-images.tar`. Класть архив в репозиторий не нужно: он большой.

Установщика Docker в проекте тоже нет. На сервере Docker ставят отдельно, до отключения интернета.

### 2. Что положить на флешку

Три вещи. Без `puls-images.tar` сервер образы не найдёт и полезет в интернет.

- `puls-images.tar` из папки проекта. Проверьте, что файл лежит рядом с `docker-compose.yml`, а не остался только на компьютере, где собирали архив.
- Саму папку проекта, но без каталогов `node_modules` и `.git` и без вашего рабочего `.env`.
- Новый файл `.env` для академии. Его делают из `.env.example` на сервере или заранее и кладут рядом с `docker-compose.yml`. Чужой `.env` с компьютера разработчика не копируют: там другой ключ и пароль базы.

Одного tar мало. Контейнеры читают исходники `backend` и `frontend` с диска сервера. Зависимости уже внутри образов, заново их скачивать не надо.

### 3. Файл `.env` на сервере

Скопируйте `.env.example` в `.env` и поправьте поля.

`SECRET_KEY` — длинная случайная строка. По ней подписываются токены входа. Текст `change-me-in-production-use-long-random-string` на сервере оставьте нельзя. На Linux:

```bash
openssl rand -hex 32
```

`CORS_ORIGINS` — адреса, которыми люди открывают сайт. Если сервер в сети академии имеет адрес `10.0.0.5`, в список входят `http://10.0.0.5:5173` и, если позже включат nginx, `http://10.0.0.5:8080`. `localhost` оставьте для входа с самого сервера.

`SEED_DEMO_DATA` на первом запуске пустой базы оставьте `true`. Тогда создадутся расположения, факультеты 1–9, причины отсутствия, медпункты, пост ДПА и учётка `admin`. Фамилии людей этот флаг не загружает: списки потом вносят в расходе из файлов. Когда структура уже есть, поставьте `false`, чтобы следующий старт ничего не дописывал. Учётка `nachalnik` создаётся при старте всегда, если её ещё нет.

`VITE_API_URL` оставьте пустым. Страница ходит в API через тот же адрес, с которого её открыли. IP бэкенда туда не пишите.

`DATABASE_URL` не меняйте на `localhost`. В Docker бэкенд подключается к базе по имени сервиса `postgres`. Compose собирает эту строку из `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB`. Если меняете пароль базы, меняйте `POSTGRES_PASSWORD`.

### 4. Первый запуск на сервере

В папке проекта на сервере:

```bash
chmod +x scripts/*.sh
./scripts/load_offline.sh puls-images.tar
```

Скрипт загружает образы из файла (`docker load`) и запускает контейнеры командой `docker compose up -d` без сборки. Потом около двух минут ждёт ответ `http://localhost:8000/api/health`.

Успех — строка `Health OK`. После неё программа работает. Если health не ответил, не запускайте `docker compose up --build`: без интернета сборка снова упадёт.

На сервере с живыми данными не запускайте:

- `docker compose up --build` и `./scripts/deploy.sh` — они пытаются заново скачать и собрать образы.
- `docker compose down -v` — флаг `-v` удаляет базу.

### 5. Как открывают сайт

С компьютера в локальной сети академии: `http://<IP-сервера>:5173`.

С самого сервера проверка API:

```bash
curl -sf http://localhost:8000/api/health
```

Ответ содержит `"status": "ok"`.

Nginx на порту 8080 не обязателен. Его включают отдельно, уже после `Health OK`:

```bash
docker compose --profile prod up -d
```

Тогда сайт открывается ещё и как `http://<IP-сервера>:8080`. Этот адрес тоже добавьте в `CORS_ORIGINS` и перезапустите контейнеры: `docker compose up -d`.

Логины — в разделе «Демо-учётки». После первого старта курсы в расходе пустые, пока в них не загрузят списки.

### 6. Обновление версии

На компьютере с интернетом снова соберите архив той же командой, что в шаге 1, и привезите новый `puls-images.tar` вместе с обновлённой папкой проекта.

На сервере сначала снимок базы, потом загрузка:

```bash
./scripts/backup.sh
./scripts/load_offline.sh puls-images.tar
```

Дамп появится в `backups/`. Если после обновления нужно вернуться назад, восстановите дамп, снятый до обновления. Одного возврата файлов мало, если схема базы уже изменилась. Подробности — в [docs/rollback.md](docs/rollback.md).

## Бэкапы и обновление

Данные живут в томе PostgreSQL (`pgdata`). Код — в git. Бэкап = снимок БД на момент создания. Снимать бэкап можно без интернета: скрипт читает уже запущенный Postgres.

Из корня проекта, когда контейнеры запущены:

```bash
./scripts/backup.sh                          # дамп → backups/asmrlsp-*.sql.gz
./scripts/restore.sh backups/asmrlsp-….sql.gz  # перезаписать БД из дампа
./scripts/deploy.sh                          # только машина с интернетом: бэкап и сборка
```

`deploy.sh` на сервере академии не используют. Там обновление — это `backup.sh`, затем `load_offline.sh`.

- Дампы старше **14 дней** удаляются при следующем `backup.sh`.
- Каталог `backups/` в git не коммитится.
- Перед `deploy.sh` в `backups/last-deploy.txt` пишутся `commit`, `backup`, время.

Ежедневный бэкап на сервере:

```cron
0 3 * * * cd /path/to/stroyuvka && ./scripts/backup.sh >>/var/log/asmrlsp-backup.log 2>&1
```

Раз в неделю скопируйте `backups/` на другой носитель. Иначе при поломке диска пропадут и данные, и копии.

Если обновление уже изменило схему БД, одного `git checkout` мало: нужен restore из дампа **до** деплоя. Подробности — в [docs/rollback.md](docs/rollback.md).

Не используйте `docker compose down -v` на сервере с живыми данными: `-v` удаляет том `pgdata`.
